## 二、字段 1:序号

### 规则
- 格式:A-1, A-2, A-3, ...(前缀 A-)
- 连续编号,中间不跳号
- 编号顺序建议:按"结果正确性 → 专业质量 → 指令遵循 → 格式 → 语气与沟通"分组(非强制)

### 机审检查
```python
# 检查序号是否连续
import re
codes = re.findall(r"A-(\d+)", document)
assert codes == list(range(1, len(codes) + 1)), "序号不连续"
```

### ❌ 错误示例
- "标准1"、"St-1"、"第一条"(不符合 A-X 格式)
- 跳号:A-1, A-2, A-4(缺 A-3)

## 三、字段 2:标准描述(核心字段,四要素结构)

### 规则

**必含四要素,缺一不可:**

| 要素 | 必填? | 作用 |
| --- | --- | --- |
| 依据或来源 | ✓ | 告诉审核员"为什么检查这条" |
| 检查什么 | ✓ | 告诉审核员"检查哪个对象" |
| 达到什么状态算合格 | ✓ | 告诉审核员"什么算通过" |
| 存在什么例外或不能推出的结论 | ✓ | 告诉审核员"边界在哪" |

### 写法模板

```
依据 [出处 1:附件 X 第 Y 条/Query 第 Z 节/培训文档规则]
     [出处 2:可选,多个依据时叠加],
检查 [验收对象 + 具体检查项];
合格条件 [通过的标准 1];[标准 2];[标准 3];...
必要边界 [不接受的写法 1];[不接受的写法 2];[边界说明].
```

### ✅ 正确示例(A-3 门店分级)

```
依据 附件《渠道与门店管理策略》第 2 章门店分级标准,
检查 A/B/C/D 各级门店的判定是否按附件阈值执行,且无"无法归类"的门店;
合格条件 按到店坪效分级:A 级 ≥ 5,000 元/㎡/月;B 级 2,000–5,000 元/㎡/月;
         C 级 1,000–2,000 元/㎡/月;D 级 < 1,000 元/㎡/月;
         租售比 > 35% 的门店不参与上述分级,直接列为 D 级;
必要边界 坪效 = 月均到店销售额 ÷ 营业面积,租售比 = 月均租金 ÷ 月均到店销售额;
         不得自行新增级别;面积调整门店需披露坪效口径失真。
```

### ❌ 错误示例

**反例 1:缺依据**
```
检查 报告应当有数据依据。
合格条件 数据要正确。
必要边界 不能编造。
```
> 问题:不知道依据哪条规则,审核员无法判断"正确"的标准

**反例 2:四要素混杂**
```
依据 Query;检查合格条件;不能造假。
```
> 问题:每要素只一句话,太笼统

**反例 3:用"专业/准确/全面"等模糊词**
```
依据 行业最佳实践,
检查 报告应当写得专业、准确、全面;
合格条件 报告应当符合行业标准;
必要边界 不能简单堆砌。
```
> 问题:违反培训文档要求"不写'基本''较好''少量''多数'"

### 机审检查
```python
# 四要素检查
required = ["依据", "检查", "合格条件", "必要边界"]
for code in a_codes:
    desc = get_standard_description(code)
    missing = [r for r in required if r not in desc]
    assert not missing, f"{code} 缺: {missing}"

# 模糊词检查
bad_words = ["基本", "较好", "少量", "多数", "大概", "差不多"]
for code in a_codes:
    desc = get_standard_description(code)
    assert not any(w in desc for w in bad_words), f"{code} 含模糊词"
```

## 四、字段 3:类型(5 类判断)

### 判断方法(培训文档 6.3.1 节)

> "按'修好它主要需要改什么'判断"

| 类型 | 验收对象 | 典型情况 | 修好要改什么 |
| --- | --- | --- | --- |
| **结果正确性** | 事实、数据、归属、计算、结论 | 金额错、名单错、状态错、计算错 | 改数字/计算 |
| **专业质量** | 方法、证据、风险、例外处理 | 材料不足下结论、归因无证据 | 改分析方法 |
| **指令遵循** | Query 明确要求的工作、范围、限制 | 漏做必做分析、超出范围 | 补做漏的工作 |
| **格式** | 文件、结构、字段、位置 | 扩展名错、字段放错、章节位置错 | 改文件结构 |
| **语气与沟通** | 表达方式、语体 | 用绝对词("必须""一定") | 改表达 |

### 关键判断规则

1. **来源 ≠ 类型**:即使 Query 明确写出要求,也不一定是"指令遵循"
   - 例:Query 要求"用员工编号关联数据",但模型按姓名合并错人数 → 应归"结果正确性"(主失败对象是结果)

2. **严重度 ≠ 类型**:不能因为问题影响大就改"结果正确性"
   - 例:漏交必需文件是"指令遵循"(关键),不是"结果正确性"
   - 例:局部措辞问题是"语气与沟通"(一般),不是"格式"

### 机审检查
```python
type_options = ["结果正确性", "专业质量", "指令遵循", "格式", "语气与沟通"]
type_count = Counter()
for code in a_codes:
    t = get_field(code, "类型")
    assert t in type_options, f"{code} 类型错误: {t}"
    type_count[t] += 1

# 数量限制
total = len(a_codes)
for t, n in type_count.items():
    max_allowed = int(total * 0.4)  # 向下取整
    assert n <= max_allowed, f"{t} 超过 40% 上限: {n}/{total}"
```

## 五、字段 4:影响程度(3 级判断)

### 判断标准(培训文档 6.3.3 节)

| 影响程度 | 判断标准 | 典型场景 |
| --- | --- | --- |
| **关键** | 改变核心结论、主要名单、重要金额;影响主要决策;使必需交付物无法使用 | 净收入算错 5%+,门店分级错、5 个交付物缺一个 |
| **重要** | 交付物整体仍能用,但有实质缺陷,需明显返工 | ROI 算错、字段部分缺失、Excel 表头错位 |
| **一般** | 局部优化问题,不影响主要结论和原定使用 | 局部措辞问题、个别字段格式 |

### 判断口诀
> "**先问:不修时,交付物能否继续按原用途使用,核心结论或执行顺序是否会改变?**"

### ❌ 错误倾向
- 把所有标准都标"关键"(失去区分度)
- 因为"影响大"就标"关键"(可能是一般表达问题)

### 建议分布(17 条参考)
- 关键 5 条 (29%)
- 重要 10 条 (59%)
- 一般 2 条 (12%)

### 机审检查
```python
impact_options = ["关键", "重要", "一般"]
for code in a_codes:
    impact = get_field(code, "影响程度")
    assert impact in impact_options, f"{code} 影响程度错误"

# 不应全是关键
impact_count = Counter(get_field(c, "影响程度") for c in a_codes)
assert impact_count["关键"] < len(a_codes) * 0.5, "关键占比超 50%"
```

## 六、字段 5:是否有中间状态

### 判断标准(培训文档 6.3.2 节)

```
"是否有中间状态"问的是:这条标准除了完全满足和不满足,
是否存在有业务意义、能够稳定判断的部分完成水平。
```

### 决策树

```
1. 这条标准只有"是/否"或"正确/错误"两种结果吗?
   → 是:选"无"
   → 否:继续
   
2. 存在可以客观区分的部分完成水平吗?
   (能用数量/比例/可定位证据区分)
   → 是:选"有"
   → 否:选"无"
```

### 典型"无"的场景
- 5 个交付物齐全 / 不齐全
- 时间口径一致 / 不一致
- 面积调整标识 3 家 / 未标识
- 文件存在 / 不存在

### 典型"有"的场景
- 50 个活动的 ROI 全部正确 / 部分错
- 42 家门店都用双指标 / 部分用单指标
- 异常 ≥ 8 条 / 5-7 条 / < 5 条

### 机审检查
```python
for code in a_codes:
    mid = get_field(code, "是否有中间状态")
    assert mid in ["有", "无"], f"{code} 是否有中间状态错误"
    
    # 如果选"无",不应该有档位字段
    if mid == "无":
        assert "中间状态档位" not in get_section(code), \
            f"{code} 选'无'但有档位"
```

## 七、字段 5b:中间状态档位(2-4 档,机审重点)

### 7.1 4 个质量要求(培训文档 6.3.2 节,缺一不可)

| 要求 | 含义 | 反例 |
| --- | --- | --- |
| **可观察** | 用数量、比例、明确条件划分 | 写"基本覆盖""大部分" |
| **不重叠** | 一个表现不能同时落入两档 | 0-4 个 + 3-7 个(3-4 重叠) |
| **无空档** | 相邻档位首尾衔接 | 0-4 个 + 8-10 个(5-7 空档) |
| **逐级递进** | 升一档需多满足一项条件 | 各档互相独立 |

### 7.2 结构化写法(机审友好)

每个档位独立一行,用"档位 N"明确编号:

```markdown
| 档位 | 标签(可选) | 描述 |
| --- | --- | --- |
| 第 1 档 | 不满足 | [基础缺失条件] |
| 第 2 档 | 部分满足 | 在上一档基础上,加 [第一层要求] |
| 第 3 档 | 满足 | 在上一档基础上,加 [最高要求] |
```

### 7.3 必含元素

- ✅ **档位编号**:第 1 档 / 第 2 档 / 第 3 档
- ✅ **标签**(可选):不满足 / 部分满足 / 满足(培训文档示例命名)
- ✅ **描述**:具体内容
- ✅ **逐级递进**:第 2/3 档必须含"**在上一档基础上**"字样
- ✅ **可观察阈值**:用数字(数量/比例)而非形容词

### 7.4 写法模板

| 档位 | 标签 | 描述(用此模式) |
| --- | --- | --- |
| 第 1 档 | 不满足 | **不满足条件**的直接陈述,如"X 缺失""Y 错误率 > X%" |
| 第 2 档 | 部分满足 | **在上一档基础上**,加 **[第一层新增要求]**;但 [遗留问题] |
| 第 3 档 | 满足 | **在上一档基础上**,加 **[第二层新增要求]**;无 [遗留问题] |

### 7.5 档位与标准描述必须显式对应(v1.1 新增规则)

**核心要求**:档位内容必须**显式列举**标准描述"检查"部分提到的所有关键对象(指标/字段/类别)。

#### ❌ 反例:隐式覆盖

```
【标准描述】
检查 6 个渠道的净收入、毛利、毛利率、客单价是否由公式严格计算得出;

【中间状态档位(错误)】
| 第 1 档 | 不满足 | 未给出 6 个渠道的净收入/毛利率明细,或任一渠道计算错误率 > 5%。 |
| 第 2 档 | 部分满足 | 在上一档基础上,6 个渠道净收入/毛利率齐全且公式正确 |
| 第 3 档 | 满足 | 在上一档基础上,6 个渠道净收入/毛利率与附件《2026H1渠道销售明细.xlsx》 严格一致 |
```

> 问题:虽然"5% 错误率"隐含覆盖了所有 4 项指标(任一错都算错误率),但**读者会困惑**——以为标准描述里说的"毛利"和"客单价"被遗漏了。

#### ✅ 正例:显式列举

```
【标准描述】
检查 6 个渠道的净收入、毛利、毛利率、客单价是否由公式严格计算得出;

【中间状态档位(正确)】
| 第 1 档 | 不满足 | 未给出 6 个渠道的 4 项指标(净收入/毛利/毛利率/客单价)明细,或任一指标计算错误率 > 5%。 |
| 第 2 档 | 部分满足 | 在上一档基础上,4 项指标(净收入/毛利/毛利率/客单价)齐全且公式正确,但口径不完全统一。 |
| 第 3 档 | 满足 | 在上一档基础上,4 项指标(净收入/毛利/毛利率/客单价)全部与附件《2026H1渠道销售明细.xlsx》 严格一致。 |
```

#### 处理对象过多的例外

如果标准描述里**关键对象超过 5 个**(无法在档位中显式列出),可使用"任一对象"的写法:

```
【标准描述】
检查 50 项合规指标(列在附件 X 第 Y 条)是否全部通过;

【中间状态档位(对象过多时)】
| 第 1 档 | 不满足 | 50 项合规指标中 ≥ 6 项不通过(>10%)。 |
| 第 2 档 | 部分满足 | 在上一档基础上,50 项指标全部计算;但 1-5 项不通过(2-10%)。 |
| 第 3 档 | 满足 | 在上一档基础上,50 项指标全部通过(0 项不通过)。 |
```

> 注意:即使"任一对象",也要**说明对象总数**("50 项"),让审核员知道全集大小。

#### 检查清单

每条 A 标准的档位写完后,问自己:

```
□ 档位内容中是否显式列出了标准描述"检查"部分提到的所有关键对象?
□ 关键对象超过 5 个时,是否说明了"全集大小"?
□ 没有用"5% 错误率"或"5% 不一致"这种隐式表达?
```

### 7.6 写法模板(完整版)

| 档位 | 标签 | 描述(用此模式) |
| --- | --- | --- |
| 第 1 档 | 不满足 | **不满足条件**的直接陈述,**显式列出标准描述的关键对象** |
| 第 2 档 | 部分满足 | **在上一档基础上**,加 **[第一层新增要求]**;但 [遗留问题] |
| 第 3 档 | 满足 | **在上一档基础上**,加 **[第二层新增要求]**;无 [遗留问题] |

### ✅ 正确示例(A-3)

| 档位 | 标签 | 描述 |
| --- | --- | --- |
| 第 1 档 | 不满足 | 42 家门店中 ≥ 6 家未按附件阈值定级(级别与到店坪效区间不符),或租售比 > 35% 的门店中 ≥ 3 家未列为 D 级。 |
| 第 2 档 | 部分满足 | 在上一档基础上,42 家均已按到店坪效区间定级且租售比 > 35% 的门店全部列为 D 级;但 1–5 家门店的到店坪效或租售比取值与附件不一致(误差 ≤ 5%)。 |
| 第 3 档 | 满足 | 在上一档基础上,42 家门店的到店坪效、租售比均可由附件数据精确复算(误差 ≤ 0.01 元),且面积调整门店(S006、S013、S031)已在《异常与待核清单》披露。 |

### ❌ 错误示例

**反例 1:无逐级递进**
```
| 第 1 档 | 不满足 | 50 个活动 ROI 全部不可复算 |
| 第 2 档 | 部分满足 | 10 个活动 ROI 可复算 |
| 第 3 档 | 满足 | 50 个活动 ROI 全部可复算 |
```
> 问题:第 2 档是"10 个",但第 3 档回到"50 个"。不递进

**反例 2:用模糊词**
```
| 第 1 档 | 不满足 | 字段大部分缺失 |
| 第 2 档 | 部分满足 | 字段基本完整 |
| 第 3 档 | 满足 | 字段全部完整 |
```
> 问题:违反"不写'基本''大部分'"规则

**反例 3:档位重叠**
```
| 第 1 档 | 不满足 | 0-5 个活动错 |
| 第 2 档 | 部分满足 | 3-7 个活动错 |
| 第 3 档 | 满足 | 5-10 个活动错 |
```
> 问题:3-5 个重叠,无法判断

### 机审检查
```python
def validate_levels(code, levels):
    """levels: [(label, desc), ...]"""
    # 1. 数量 2-4
    assert 2 <= len(levels) <= 4, f"{code} 档位 {len(levels)} 个,需 2-4"
    
    # 2. 逐级递进:第 2 档+ 必须含"在上一档基础上"
    for i, (label, desc) in enumerate(levels[1:], 1):
        assert "在上一档基础上" in desc, \
            f"{code} 第{i+1}档缺'在上一档基础上'"
    
    # 3. 无模糊词
    bad = ["基本", "较好", "少量", "多数", "大概", "差不多", "大部分", "几乎"]
    for label, desc in levels:
        for w in bad:
            assert w not in desc, f"{code} '{label}' 档含模糊词'{w}'"
    
    # 4. 可观察:必须含数字或明确条件
    # 简化:含数字或 ≥/≤/> 等比较符
    for label, desc in levels:
        has_observable = bool(re.search(r'\d|≥|≤|>|<|百分之|第', desc))
        assert has_observable, f"{code} '{label}' 档不可观察"
```

## 八、数量与分布(硬性要求)

### 8.1 最低数量

| 项 | 要求 |
| --- | --- |
| 总条数 | **≥ 15 条** |
| 结果正确性 | ≥ 4 条(5 选 1 中至少这个数) |
| 专业质量 | ≥ 4 条 |
| 指令遵循 | ≥ 2 条 |
| 格式 | ≥ 2 条 |
| 语气与沟通 | ≥ 1 条 |

### 8.2 上限

| 类型 | 上限(40% 规则) | 公式 |
| --- | --- | --- |
| 任一类型 | 总条数的 40%(向下取整) | `int(total * 0.4)` |
| 例:15 条 | 6 条 | `int(15 * 0.4) = 6` |
| 例:17 条 | 6 条 | `int(17 * 0.4) = 6.8 → 6` |
| 例:20 条 | 8 条 | `int(20 * 0.4) = 8` |

## 九、命名一致性(机审高发错误)

### 9.1 附件名必须带扩展名

```
❌ 《2026H1渠道销售明细》               # 漏 .xlsx
✅ 《2026H1渠道销售明细.xlsx》          # 含扩展名

❌ 《华东区门店租约汇总》               # 漏 .docx
✅ 《华东区门店租约汇总.docx》          # 含扩展名
```

### 9.2 Sheet 名必须与实际一致

```
❌ "渠道销售明细 Sheet 与月度汇总 Sheet"  # 把两个 Sheet 混为一谈
✅ "渠道销售明细 Sheet 和 渠道月度汇总 Sheet"  # 明确两个 Sheet

❌ "门店月度经营 Sheet"                  # 实际叫"门店月度经营",但引用名要带 Sheet 后缀
✅ "门店月度经营 Sheet"                  # 引用名带 Sheet 后缀,但 Sheet 名本身是"门店月度经营"
```

### 9.3 字段名必须与 Query 一致

```
❌ 标准描述里写"调价建议"
✅ 标准描述里写"调整建议"  # 与 Query 字段名一致
```

### 9.4 不得用模型名/标准答案

```
❌ "M1 报告中应当..."
✅ "报告应当..."

❌ "标准答案是 X"
✅ 不写标准答案,只写"合格条件"
```

## 十三、自动化机审脚本(伪代码)

```python
"""
A 模块自动机审脚本 - validate_a_module.py
"""
import re
import openpyxl
from pathlib import Path
from collections import Counter

def validate(document_path: Path, input_dir: Path) -> dict:
    content = document_path.read_text()
    issues = []
    
    # 1. 提取所有 A 标准
    sections = parse_a_sections(content)
    
    # 2. 字段完整性
    for code, sec in sections.items():
        for field in ["类型", "影响程度", "是否有中间状态"]:
            if field not in sec:
                issues.append(f"{code} 缺字段: {field}")
    
    # 3. 标准描述四要素
    for code, sec in sections.items():
        for elem in ["依据", "检查", "合格条件", "必要边界"]:
            if elem not in sec:
                issues.append(f"{code} 缺四要素: {elem}")
    
    # 4. 模糊词
    bad_words = ["基本", "较好", "少量", "多数", "大概", "差不多", "大部分", "几乎"]
    for code, sec in sections.items():
        for w in bad_words:
            if w in sec:
                issues.append(f"{code} 含模糊词: {w}")
    
    # 5. 档位质量
    for code, sec in sections.items():
        if "是否有中间状态" in sec and "**有**" in sec:
            levels = re.findall(r"\| 第 (\d+) 档 \|", sec)
            assert 2 <= len(levels) <= 4, f"{code} 档位 {len(levels)} 个"
            
            # 逐级递进
            for i in range(2, len(levels) + 1):
                if f"| 第 {i} 档 |" in sec:
                    # 找该档描述
                    m = re.search(rf"\| 第 {i} 档 \|.*?\n\| 第 (?:{i+1}|\d+ \w+\|)", sec, re.DOTALL)
                    if m and "在上一档基础上" not in m.group(0):
                        issues.append(f"{code} 第 {i} 档缺'在上一档基础上'")
    
    # 6. 数量
    total = len(sections)
    if total < 15:
        issues.append(f"总条数 < 15: {total}")
    
    # 7. 类型分布
    types = Counter(re.search(r"\| 类型 \| (.+?) \|", sec).group(1).strip()
                    for sec in sections.values() if "| 类型 |" in sec)
    min_required = {"结果正确性": 4, "专业质量": 4, "指令遵循": 2, "格式": 2, "语气与沟通": 1}
    for t, n in min_required.items():
        if types.get(t, 0) < n:
            issues.append(f"{t} 不足 {n}: {types.get(t, 0)}")
    
    # 8. 上限
    for t, n in types.items():
        if n > int(total * 0.4):
            issues.append(f"{t} 超 40% 上限: {n}/{total}")
    
    # 9. 命名一致性
    actual_files = {f.name for f in input_dir.iterdir()}
    for ref in re.findall(r"《([^》]+)》", content):
        if not ref.endswith((".xlsx", ".docx")) and not any(kw in ref for kw in ["建议", "报告", "策略", "清单"]):
            issues.append(f"附件名可能漏扩展名: 《{ref}》")
    
    # 10. 禁止词
    for w in ["M1", "M2", "M3", "标准答案", "正确答案"]:
        if w in content and w not in ["M1 ", "M2 ", "M3 "]:  # 排除误识别
            count = content.count(w)
            if count > 0:
                issues.append(f"出现禁止词 '{w}': {count} 次")
    
    return {
        "total": total,
        "types": dict(types),
        "issues": issues,
        "pass": len(issues) == 0
    }
```

一、这个项目在做什么
建设一批能检验 AI 是否真的会完成专业工作的高质量任务。专家不需要懂模型和编程，只需要用真实工作经验，把：

真实业务怎么发生；

需要什么材料；

要做哪些专业判断；

什么结果算做好；
讲清楚，并评价模型产物。

二、产线里的 6 个核心对象
任务说明：给系统的任务背景说明，不是正式题目。

附件：真实业务材料，是事实和规则来源。

Query：最终给模型的正式任务书。

M1 / M2 / M3：三个模型分别产出的候选成果。

评估表：专家对优秀标准、模型缺点、敏感红线的评价。

专家 Solution：专家按当前 Query 和附件亲自完成的可交付成果。

三、好任务的四个标准
真实：来自真实岗位，不是临时拼场景。

可解：核心事实、规则、材料都在题内。

专业：需要判断、跨材料核对、多步计算、例外处理或业务取舍。

可验收：交付物明确，能判断对错。

硬门槛：

任务步数 ≥ 25 步，否则退回重设。

预计任务耗时 ≥ 480 分钟，低于直接拒绝。

不能靠故意缺信息、设置陷阱、堆噪音来增加难度。

四、评估表 A / B / C 的核心口径
模块 A：优秀结果标准
至少 15 条，不设上限。

类型最低要求：

结果正确性 ≥ 4

专业质量 ≥ 4

指令遵循 ≥ 2

格式 ≥ 2

语气与沟通 ≥ 1

任一类型不得超过实际总条数的 40%。

每条要写清：依据 + 验收对象 + 合格条件 + 必要边界。

来源只能是：Query 明示、附件支持、行业共识/专业默认规则。

模块 B：模型缺点反推
v3.0 新版要求：

影响程度为关键/重要的评估项中，至少两家“不满足”的不少于 10 条；

其中三家都“不满足”的不少于 6 条；

只有一家“不满足”的至少 1 条。

每条先写通用「评估项描述」，再填 M1/M2/M3 三家情况，再写模型证据。

证据格式：原文或具体表现 + 文件名 + 位置。

模块 C：敏感红线
只用于极高敏感内容：

伦理问题、隐私泄露、政治错误、色情或暴力、其他极高敏感。

普通计算错误、漏做任务、专业不足、格式问题，即使严重，也不能放进 C。

五、附件要求
核心附件原则上至少 5 个，且真实使用。

默认至少两类不同文件类型；特定领域可例外，但要满足条件。

至少一个附件标记为私有。

噪音建议不超过附件总数的 30%。

ZIP 压缩包内不能有文件夹。

附件提交后进入平台脱敏，专家无需自行脱敏，但可先自行脱敏。

六、流程与退回
主流程：
附件 + 任务说明 → 附件机审 → Query 提交 → 题目机审 → 步数检查 → M1/M2/M3 → 评估表 → Solution → 初审 → 复审 → 一阶段通过/拒绝。

退回时只改当前状态允许编辑的内容：

附件问题退回“附件待提交”；

Query 问题退回“题目待提交”；

评估表问题退回“专家评估中”；

Solution 问题退回“Solution 待提交”。

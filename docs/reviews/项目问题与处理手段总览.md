## 五、本轮沉淀的七条元层面教训

1. **模型异常清单必须逐条独立复算再采信**:M3 的 16 条里 1 条是误报(A-004),若不复核就写进材料问题清单,
   会把"模型误判"当成"材料缺陷"传递给下一环节。判定要点:**先用材料自身的字段语义定义去验,再质疑材料**。
2. **"分项 + 合计"要自校验**:A-006 的三处分项全对、合计却错(549 vs 481)——单看分项发现不了,
   必须做一次加总校验,这类错误在报告正文里同样会出现。
3. **许可性条款的触发条件是"历史事实"**:制度里的"连续 N 个月""累计达到"等条件一旦满足即为已触发;
   以"当期回落"推翻触发条件(S028)会让处置方向偏离制度,应在依据中写明"已触发但选择不采用"的理由。
4. **规范类问题在产物侧仍普遍存在**:M3 的 137 + 18 处、M2 的 334 处(324 + 10)、M1 的 1,132 处引用不规范——
  依据必须写成"完整文件名 + 扩展名 + Sheet + 字段",否则评审无法定位;依据列越多,规范风险越大。
5. **照抄制度措辞会把口径歧义带进产物**(M1 `YC-30`):"即时配送归即时零售渠道"这句制度用语被原样写进
  履约结构分析,而数据里 584,912.78 元即时配送净收入中有 406,886 元归 CH01–CH05。教训:
   **引用制度用语前,必须回到数据字段核对它在数据上是否成立**(M-01 因此只有 M3 识别出来)。
6. **发现能力取决于是否做跨字段核验**:M1 做了大量单指标复算(30 条异常、数值逐位精确),
   但未把 `发货方式` 与 `渠道ID` 交叉核验,因而漏掉 M-01;M2 同样未做该交叉核验(反而把 M-01 写成确定结论);
   只有 M3 做了这次交叉核验,因而发现。教训:
   **单指标复算再准,也替代不了跨字段、跨口径的交叉验证**。
7. **"许可性口径"不得写成"已确认事实"**(M2):制度第 3.2 条可读作"即时配送订单归即时零售渠道",
   数据实现却是按 `渠道ID` 归集;M2 直接把该措辞写成"**即时配送收入仍归 CH06**"的两处确定结论,
   与自身交付物(渠道清单 CH06 净收入 238,360.01 元)自相矛盾。教训:
   **当制度措辞与数据实现存在两种可能解释时,产物应写"本次采用的口径 + 另一种口径的影响",而不是二选一写成定论**。
